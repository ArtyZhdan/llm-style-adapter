# Инструкция: расширение обучающего датасета через Kimi

Цель: **100 примеров на стиль** = 25 исправленных существующих + 75 новых.
Результат для каждого стиля сохраняем в два файла (см. «Куда сохранять»).
После генерации ассистент проверит данные, соберёт финальные train-файлы,
и только потом (с отдельного согласия) начнём обучение.

---

## Общие правила данных (действуют на оба стиля)

1. **Формат — строгий JSONL**: один объект на строку, ключи ровно
   `instruction`, `input`, `output`. Кириллица без экранирования,
   переносы строк внутри текста — как `\n`. Никаких пояснений вне JSONL.
2. **Фактология**: все числа, суммы, проценты, даты, имена, названия
   из `input` переносятся в `output` **точно** (допустимо писать словами:
   «13» → «тринадцати», но нельзя менять значение). Нельзя добавлять
   факты, которых нет в `input`. Ироническая оценка допустима, но она
   должна быть оценкой, а не выдуманным фактом.
3. `input` — нейтральный новостной текст 2–5 предложений, без стиля,
   без эмодзи, без заголовков.
4. **Запрещённые темы** (тестовый набор, его трогать нельзя): цифровой
   рубль и тесты ЦБ; микрочипирование домашних животных; тарифы
   доставки в непогоду; изоляционный эксперимент SIRIUS; микроквартиры
   и студии малой площади.
5. Темы не должны дублировать темы существующего train-файла стиля
   (Kimi его получит в контексте) — только новые сюжеты.

---

## Фаза А. Исправление существующих 25 примеров (на стиль)

Сначала вставь в чат **весь текущий файл** `data/train_type1.jsonl`
(или `data/train_type2.jsonl` — по очереди), затем промт:

````text
Выше — обучающие примеры в JSONL: поля instruction, input, output.
Твоя задача — выдать ИСПРАВЛЕННУЮ версию каждой строки (все 25, те же
порядок и input, изменён только output), строго в формате JSONL,
один код-блок, без пояснений.

Правки:
1. Все числа/суммы/проценты/даты/имена должны точно соответствовать
   input (например, диапазон «5-8 лет» нельзя сужать до «5 лет»;
   «от 3500 до 6000 рублей» нельзя менять на «от 4000»; «до 50% ферм»
   нельзя превращать в «полностью исчезнет»). Ирония и сарказм —
   сохранить, меняются только искажённые факты.
2. Структуру, длину и стиль ответов менять минимально.
3. [type1] Каждый output заканчивается тегом «@banki_oil» — проверь,
   что он есть и стоит в конце через пробел.
4. [type2] Заголовок в начале output (после эмодзи) оформи жирным
   markdown-разметкой: одна пара **...** вокруг всего заголовка.
   Пример: «🚇 **На Кольцевую вышел новый поезд.**» Остальной текст
   без изменений, эмодзи только в самом начале.
````

## Фаза Б. Новые примеры (75 на стиль, батчами по 12)

В том же чате (контекст файла уже есть) отправляй промт ниже,
пока не наберёшь 75 новых строк (7 батчей: 6×12 + 1×3):

````text
Сгенерируй 12 НОВЫХ обучающих примеров в том же JSONL-формате
(instruction, input, output) для стиля [type1: @banki_oil / type2: @moscowach].

Требования к новым примерам:
- Новые темы (не из файла выше, не из запрещённого списка:
  цифровой рубль, чипирование животных, тарифы доставки в непогоду,
  SIRIUS, микроквартиры). Разнообразь сюжеты: экономика и цены,
  технологии, транспорт, ЖКХ, здравоохранение, образование, курьёзы,
  законодательные инициативы.
- input: нейтральная новость 2–5 предложений с конкретными фактами
  (числа, суммы, проценты, сроки) — их output обязан сохранить точно.
- output: 40–90 слов.
- instruction: чередуй формулировки из списка ниже, примерно равномерно.
- Один код-блок JSONL, без пояснений.

[ type1 — вставить этот блок ]
Формулировки instruction (чередовать):
1. «Перепиши новостной текст в стиле Telegram-канала @banki_oil.»
2. «Перепиши новость в стиле финансово-аналитического Telegram-канала @banki_oil.»
3. «Перескажи новость коротко и иронично, как @banki_oil.»
4. «Оформи новость в формате поста канала @banki_oil.»
Стиль output: сухой, ироничный аналитический тон; 2–4 коротких
предложения; акцент на цифрах и фактах исходника; финальная фраза —
лёгкая ирония или саркастичная «добивка» (оценка, не новый факт);
завершается « @banki_oil»; без эмодзи и markdown-разметки.

[ type2 — вставить этот блок ]
Формулировки instruction (чередовать):
1. «Перепиши новостной текст в стиле Telegram-канала @moscowach: эмодзи, **жирный заголовок**, короткие абзацы.»
2. «Оформи новость как пост городского канала @moscowach: эмодзи, **жирный заголовок**, короткие абзацы.»
3. «Перепиши новость в московском городском формате @moscowach.»
Стиль output: первый абзац — ОДИН эмодзи + пробел + заголовок
**жирным markdown** (одно цепляющее предложение); затем пустая строка
и 1–3 коротких абзаца по 1–3 предложения; простой живой язык;
итого 40–80 слов; без тега канала; эмодзи только в самом начале.
````

---

## Куда сохранять

- Исправленные старые: `data/train_type1_fixed.jsonl`, `data/train_type2_fixed.jsonl`
- Новые: `data/train_type1_new.jsonl`, `data/train_type2_new.jsonl`

Как: каждый код-блок от Kimi — скопировать целиком и дописать
(append) в соответствующий файл, без ```-оград и без пустых строк
между объектами. Файлы должны быть в кодировке UTF-8.

## Порядок действий

1. Фаза А для type1 → `data/train_type1_fixed.jsonl` (2–3 батча по 12).
2. Фаза А для type2 → `data/train_type2_fixed.jsonl` (2–3 батча по 12).
3. Фаза Б для type1 → `data/train_type1_new.jsonl` (7 батчей).
4. Фаза Б для type2 → `data/train_type2_new.jsonl` (7 батчей).
5. Сообщить ассистенту — он проверит данные (JSON-валидность, сверка
   чисел с input, дубли, соответствие стилю) и соберёт финальные
   train-файлы. Обучение начинается только после отдельного согласия.
