# Инструкция для генерации обучающих примеров v5 (датасет дообучения стилей)

## Задача

Сгенерировать **50 новых обучающих примеров** на каждый из двух стилей Telegram-каналов.
Каждый пример = нейтральная новость (input) + переписанный в целевом стиле текст (output).
**Одни и те же 50 input** должны быть в обоих файлах (пример N — одна новость в обоих
файлах; это нужно для сравнения стилей, на обучение попарность не влияет).

Файлы для заполнения (в корне проекта):
- `data/train_type1_v5_new.jsonl` — стиль @banki_oil
- `data/train_type2_v5_new.jsonl` — стиль @moscowach

## Формат файлов

JSONL: каждая строка — один JSON-объект, без запятых между строками:

```json
{"instruction": "<один из вариантов системного промпта ниже>", "input": "<нейтральная новость>", "output": "<текст в целевом стиле>"}
```

Важно: переносы строк внутри output (для type2) записываются как `\n\n` — это два
символа backslash+n в JSON-строке, а не реальный перенос строки внутри JSONL-строки.

## Требования к input (нейтральной новости)

- Русский язык, нейтральный новостной тон. Основная масса — **40–80 слов**, но
  **10–15 примеров обязаны быть длинными: 100–150 слов** — это важно: наш тестовый
  набор состоит именно из длинных плотных новостей, и на них модель ошибается чаще.
- Реалистичная современная новость, без фантастики и абсурда.
- **Минимум 3 конкретных числа** (даты, суммы в рублях, проценты, метры, количество людей).
  Примерно треть новостей — с 5+ числами, длинные новости (100–150 слов) — с 6+ числами.
- Примерно треть новостей — «сложные случаи»:
  - похожие числа, которые легко перепутать (0,3% и 3%; 1,5 млн и 15 млн);
  - цитата с именем и должностью (их нужно сохранять в output);
  - несколько разных фактов, которые нельзя смешивать (кто, что, где, когда — отдельно).
- Темы — повседневная городская и экономическая жизнь: транспорт, ЖКХ, ритейл, технологии,
  здоровье, образование, законы, экология, энергетика, культура, городская инфраструктура.
  Темы внутри выборки не повторяются.
- Каждая новость — самостоятельный факт, без продолжений сюжета от примера к примеру.

## Требования к output: стиль type1 (@banki_oil)

- **35–70 слов**, короткий связный текст: факты новости + холодная аналитика.
- **КАЖДЫЙ пример обязан завершаться ироничной/колкой добивкой** — 1–2 заключительных
  предложения с саркастическим обобщением ситуации (не новый факт, а оценка/колкость
  по смыслу новости). Без добивки пример бракованный.
- В добивке **не используйте числа** (чистый сарказм без цифр) — так её проще
  проверять автоматически и надёжнее воспроизводить.
- В самом конце — тег через пробел: `...фраза. @banki_oil`
- Без эмодзи, без markdown-разметки, без заголовка.
- **Числовая дисциплина (жёстко):** все числа из input переносятся в output без
  искажений; запрещены любые числа, которых нет в input.

## Требования к output: стиль type2 (@moscowach)

- Первая строка: **один эмодзи + пробел + `**жирный заголовок**`** (заголовок короткий
  и точный — без преувеличений и без цифр, которых нет в тексте новости).
- Затем **2–4 коротких абзаца** через пустую строку (`\n\n`), каждый абзац 1–2 предложения.
- Общий объём 25–70 слов.
- **Числовая дисциплина — та же, жёстко.**

## Поле instruction: ротируйте 4 варианта поровну

type1 (по ~12–13 примеров на вариант):
1. `Перепиши новостной текст в стиле Telegram-канала @banki_oil.`
2. `Перепиши новость в стиле финансово-аналитического Telegram-канала @banki_oil.`
3. `Перескажи новость коротко и иронично, как @banki_oil.`
4. `Оформи новость в формате поста канала @banki_oil.`

type2 (по ~12–13 примеров на вариант):
1. `Перепиши новостной текст в стиле Telegram-канала @moscowach (городской новостной формат с эмодзи в начале, жирным заголовком и короткими абзацами).`
2. `Перепиши новостной текст в стиле Telegram-канала @moscowach: эмодзи, **жирный заголовок**, короткие абзацы.`
3. `Оформи новость как пост городского канала @moscowach: эмодзи, **жирный заголовок**, короткие абзацы.`
4. `Перепиши новость в московском городском формате @moscowach.`

## Образец одного примера (input один, output два)

input:

```
Мосгордума утвердила пилотный проект по запуску беспилотных автобусов на три маршрута в Новой Москве с 1 марта. В первой фазе на линию выйдут пять автобусов вместимостью 22 пассажира, скорость движения составит до 60 км/ч. Проезд будет бесплатным в течение первых шести месяцев, затем тариф сравняется с билетом наземного транспорта — 57 рублей. В департаменте транспорта заявили, что беспилотники снизят расходы на перевозки на 18% к 2027 году.
```

output для type1:

```
С 1 марта по Новой Москве начнут курсировать беспилотные автобусы: пять машин, три маршрута, 22 пассажира, скорость до 60 км/ч. Проезд полгода будет бесплатным, потом сравняется с обычным билетом — 57 рублей. В департаменте транспорта обещают сократить расходы на перевозки на 18% к 2027 году. Город учит автобус ездить без водителя, а водителей — при этом пока никто не учит. @banki_oil
```

output для type2:

```
🚌 **По Новой Москве поедут беспилотные автобусы — полгода бесплатно.**

С 1 марта пять беспилотных автобусов выйдут на три маршрута. Машины вмещают 22 пассажира и едут со скоростью до 60 км/ч.

Первые шесть месяцев проезд бесплатный. Потом тариф сравняется с обычным билетом — 57 рублей.

В департаменте транспорта заявили, что беспилотники снизят расходы на перевозки на 18% к 2027 году.
```

## Чек-лист перед сохранением файлов

1. В каждом файле ровно 50 строк, каждая — валидный JSON с ключами только
   `instruction`, `input`, `output` (без лишних ключей, без запятых в конце строк).
2. `input` в обоих файлах идентичен построчно (пример N — одна и та же новость).
3. Все числа из input присутствуют в output в неизменном виде; в output нет чисел,
   которых нет в input.
4. type1: добивка есть в КАЖДОМ примере, в конце каждого output — ` @banki_oil`.
5. type2: каждый output начинается с эмодзи и `**жирного заголовка**`, абзацы разделены `\n\n`.
6. instruction — только из списка выше, 4 варианта ротируются примерно поровну.

## Практический совет по генерации

Генерируйте партиями по 10 примеров (пять input с двумя output), чтобы ответ не обрезался.
После каждой партии сверяйтесь с чек-листом, затем дописывайте следующую партию в конец файла.
